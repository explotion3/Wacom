## Future builder ownership

A future SerpentWood content builder may write only the 38 package paths above. The four existing cards are read-only. The builder must not save Journey/Floor/map, Debug/Authoring content, Player/Host Blueprint, TrainingWarrior, UI, material, texture, card-presentation or backpack packages.

The implementation round must add package hash/dirty guards for the read-only dependencies and run the builder twice to verify stable IDs, references, counts and field values. Binary package hash equality is required only where the chosen builder contract explicitly promises deterministic serialization; otherwise semantic re-load validation remains authoritative.

## Naming and identity rules

- Asset filename is an authoring locator; the internal stable content ID is the rule identity.
- IDs are never inferred from path or display text.
- Renaming a package requires reference migration but does not silently rename the internal ID.
- DisplayName, description, art and world transform are not stable identity.
- Production assets cannot be created by renaming or copying a test/debug fixture without rebuilding every internal reference and passing the future validation gate.
