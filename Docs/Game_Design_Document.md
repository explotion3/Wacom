# Game Design Document

本文是当前项目的简版 GDD，用于确定游戏的大致玩法、体验目标和第一阶段开发边界。更细的战斗规则以 `FirstPerson_HD2D_Card_Variant.md` 和后续拆分出的规则文档为准。

## 1. 游戏概述

本项目是一款单人第一人称 HD-2D 卡牌冒险游戏。

玩家可以选择一个角色进入一个可探索区域中前进、遭遇敌人、收集卡牌、调整背包，并通过一场场高风险的部位制卡牌战斗推进 Run。游戏的核心体验不是传统卡牌游戏中的“消耗能量打牌”，而是围绕手牌位置、敌人部位先机和完美释放窗口做判断。

### 核心卖点

- 第一人称 HD-2D 表现：玩家角色以第一人称面对敌人，敌人以多部位 HD-2D 角色呈现在画面前方。
- 部位制敌人：敌人由头、身体、尾巴等多个部位组成，每个部位有自己的生命、意图和先机。
- Cost 风险模型：卡牌 `Cost` 不消耗玩家资源，而是扣减所有敌方存活部位的先机，可能提前触发敌人行动。
- 空间手牌：手牌被左手牌、右手牌切成左手区、双手区、右手区，不同区域会改变卡牌价值。
- 背包构筑：战斗外背包保存永久卡牌池，玩家在战斗前从背包中选择卡牌组成战斗卡组。

## 2. 目标体验

玩家每一回合都应该面对清晰但有压力的选择：

- 现在打高 Cost 牌能获得强效果，但可能让多个敌人部位立刻行动。
- 低 Cost 牌更安全，但可能错过完美释放或关键击破窗口。
- 同一张牌处在不同手牌区域时，价值可能完全不同。
- 打出左手牌或右手牌会改变整个手牌结构，带来短期收益和区域失效风险。
- 击破敌人关键部位可以改变战斗节奏，但敌人并不一定立刻死亡。

游戏应当让玩家感觉自己在“观察敌人动作、调整手牌位置、抓住释放时机”，而不是只是在按费用曲线打牌。

## 3. 游戏循环

### Run 循环

```text
进入区域
-> 探索
-> 遭遇战斗 / 事件 / 商店 / 休息
-> 获得或调整卡牌
-> 继续探索
-> 挑战区域 Boss
-> 进入下一区域或结束 Run
```

第一阶段先不实现完整自由探索 Run。项目需要一个测试场景，场景中放置一个用于开发验证的战斗 Actor。玩家与该 Actor 交互后触发一次测试战斗，用来验证以下原型循环：

```text
进入测试场景
-> 与战斗 Actor 交互
-> 开始战斗
-> 战斗胜利 / 失败
-> 返回测试场景入口或战斗 Actor 附近
-> 可以再次触发测试战斗
```

该测试入口只服务第一阶段开发验证，不代表正式 Run 结构。

### 战斗循环

```text
战斗开始
-> 初始化玩家生命、战斗卡组、敌人部位
-> 玩家回合开始抽牌
-> 玩家执行回合操作：打牌 / 等待 / 结束回合
-> 敌人部位可能因先机归零在玩家回合内行动
-> 玩家主动结束回合
-> 存活部位按顺序行动
-> 进入下一回合
-> 全部部位破坏后胜利 / 玩家生命归零后失败
```

### 玩家回合操作

玩家回合内至少支持三类操作：

- 打牌：选择手牌中的卡牌并选择合法目标，结算卡牌效果、完美释放和先机扣减。
- 等待：玩家不打出卡牌，而是主动推进敌人部位先机。等待有一个当前等待值，初始值由规则或战斗配置提供。每次等待时，敌人所有存活部位当前先机减少当前等待值；等待结算后，当前等待值增加 1。
- 结束回合：玩家主动结束当前回合，所有存活且可行动的敌人部位按部位顺序执行当前意图并刷新意图。

等待用于提供一种不消耗手牌的节奏调节手段。它可以帮助玩家靠近完美释放窗口，也可能提前触发敌人部位行动，因此同样属于风险操作。

## 4. 玩家



玩家拥有：

- 当前生命值。
- 生命值上限。
- 战斗卡组。
- 抽牌堆、手牌、弃牌堆、消耗区。
- 战斗外背包。
- 左手牌和右手牌。

主要限制来自卡牌条件、手牌位置、敌人先机风险和卡牌自身规则。

### 手与手指

玩家角色默认拥有左手牌和右手牌。左右手牌不仅是手牌区域锚点，也代表玩家角色的双手。

玩家角色默认拥有 10 个手指。手指是通用身体资源，会影响玩家最大生命值。失去手指代表失去最大生命值。

每次失去手指时，玩家的左手牌或右手牌都会发生相对应的卡面变化。失去 5 个手指后，玩家会失去一张左右手牌。先失去左手牌还是右手牌暂定。

手指系统会影响角色生命、左右手牌、手牌区域结构和部分角色专属任务，因此不应只作为叙事文本处理。

## 5. 卡牌

卡牌是玩家战斗和成长的核心。

### 基础属性

卡牌至少包含：

- 名称。
- Cost。
- 可选的身材。
- 类型或词条。
- 稀有度。
- 效果。
- 可选的被动。
- 可选的区域效果。
- 可选的完美释放效果。

身材用于记录卡牌进入战斗或作为长期物品时提供的基础属性，例如生命值上限、耐久、容量等。不是每张卡都必须拥有身材。

被动用于记录不需要主动打出也能持续检查或响应事件的效果，例如“每当你打出三张伙伴时，使此牌回到手中”。被动应和主动打出效果区分记录。

### Cost

`Cost` 表示打出该牌后减少敌方所有存活部位的当前先机值。

Cost 不代表玩家资源消耗。战斗中可以出现 `Runtime Cost` 修正，完美释放判断和先机扣减都使用当前 `Runtime Cost`。

### 关键词方向

已出现或计划出现的关键词包括：

- 迅捷：打出时不减少敌方部位先机，也不触发完美释放。
- 伙伴：一种卡牌词条，不作为可被攻击的场上实体。
- 连击：使用后可重复使用。
- 保留：回合结束时不弃掉。
- 突袭：暂未定义，

## 6. 手牌空间

手牌不是普通线性列表，而是由左手牌和右手牌切分出的空间结构。

```text
[左手区] [左手牌] [双手区] [右手牌] [右手区]
```

### 左手牌与右手牌

左手牌和右手牌既是区域锚点，也是普通卡牌。它们可以被打出、弃掉或被事件影响。

当左手牌或右手牌离开手牌时，双手区立刻失效。原本位于双手区的卡牌仍然留在手牌中，但不再满足双手区条件。

### 腾挪

腾挪表示重新放置当前手牌中的卡牌，使其进入不同区域，或在同一区域内改变位置。

腾挪是本游戏区别于普通卡牌战斗的重要操作，它让玩家通过调整手牌空间来制造区域效果、完美释放机会和 Cost 转移。

## 7. 敌人

敌人由多个部位组成。每个部位近似一个独立的战斗单元。

每个部位拥有：

- HP。
- 当前意图。
- 当前先机。
- 状态。
- 部位顺序。

部位 HP 归零后进入破坏态。破坏部位不再参与先机扣减、意图刷新和行动结算。

敌人只有全部部位被破坏后才算战斗胜利。部分关键部位被破坏时可以触发击倒事件或奖励事件，但不等于敌人死亡。

## 8. 先机与完美释放

先机是敌人部位的行动倒计时。

玩家打出非迅捷卡牌后，所有存活部位的当前先机减少该牌 `Runtime Cost`。如果部位先机归零或低于零，该部位按固定顺序行动，然后刷新意图和先机。

完美释放用于奖励精确打牌：

- 出牌前记录所有存活部位的当前先机。
- 如果卡牌 `Runtime Cost` 正好等于某个部位的出牌前先机，则该部位命中完美释放。
- 多个部位可以同时命中。
- 迅捷卡不触发完美释放。

完美释放应当成为玩家主动规划的关键收益，而不是偶然出现的小加成。

## 9. 背包与构筑

背包是战斗外永久卡牌池。

玩家在战斗开始前从背包中选择一部分卡牌组成战斗卡组。背包有容量上限，容量可以通过卡牌、事件或成长系统提升。

部分卡牌进入战斗时会提供生命值上限等入战属性。此类效果在卡牌进入战斗时立即生效。

第一阶段暂不实现完整背包，只在规则和数据设计中保留该方向。

## 10. 探索与 Run

长期方向是区域探索式 Run，而不是固定路线节点。

区域中可以包含：

- 普通战斗。
- 精英战斗。
- 区域 Boss。
- 商店。
- 事件。
- 休息点。
- 成长或卡牌管理点。

探索部分应服务于卡牌构筑和战斗准备，不应削弱战斗作为核心玩法的地位。

## 11. 美术与表现方向

游戏采用第一人称 HD-2D 表现。

### 战斗画面

- 敌人部位需要有明确视觉分区。
- 意图和先机应靠近对应部位显示。
- 手牌位于画面下方，保留左手、双手、右手的空间感。
- 打出左手牌或右手牌时，手牌结构变化需要有清晰反馈。

### 氛围方向

当前卡牌示例包含昆虫、暮色、毒、冻结、暮气等意象。美术可以向自然、微光、昆虫、腐殖、潮湿洞穴和黄昏生态靠拢。

## 12. 第一阶段原型目标

第一阶段只验证战斗核心。

必须实现：

- 单玩家。
- 一个测试敌人：蛇。
- 蛇有头、身体、尾巴三个部位。
- 每个部位有 HP、Intent、CurrentInitiative。
- 玩家回合开始抽 5 张。
- 手牌拥有左手区、双手区、右手区。
- 打牌按 Cost 扣所有存活部位先机。
- 完美释放按出牌前先机判断。
- 多部位归零后按部位顺序行动。
- 玩家结束回合时，所有存活可行动部位按顺序行动。
- 部位 HP 归零后进入破坏态。
- 全部部位破坏后战斗胜利。



## 13. 设计原则

- 先验证战斗节奏，再扩展 Run 外层。
- 先保证规则可读，再追求复杂卡牌组合。
- Cost 是风险，不是资源。
- 手牌位置是策略，不只是 UI 排列。
- 敌人部位要提供不同威胁，而不只是多个血条。
- 所有长期系统都应服务于卡牌构筑、战斗准备和战斗中的判断压力。
