## §1 游戏概述

本项目是一款**单人第一人称 HD-2D 卡牌冒险游戏**。

玩家选择一个角色进入可探索区域，在昼夜循环和压力消耗下推进 Run，遭遇敌人、收集卡牌、调整背包，通过一场场高风险的部位制卡牌战斗推进。

### 核心卖点

- **第一人称 HD-2D 表现**：玩家以第一人称面对敌人，敌人以多部位 HD-2D 角色呈现在画面前方。
- **部位制敌人**：敌人由头、身体、尾巴等多个部位组成，每个部位有自己的生命、意图和先机。
- **Cost 风险模型**：卡牌 `Cost` 不消耗玩家资源，而是扣减所有敌方存活部位的先机，可能提前触发敌人行动。
- **空间手牌**：手牌被左手牌、右手牌切成左手区、双手区、右手区，不同区域改变卡牌价值。
- **背包构筑**：背包是永久卡牌池，玩家在背包界面调整备战卡组。战斗只读备战卡组。
- **战内 / 战外解耦**：战斗内只决输赢，战损不带出战外。战外用压力系统承接战损与节奏消耗。
- **昼夜节奏**：一天分五时段，节点是流程最小单位也是资源点，玩家在有限节点内完成探索 / 战斗 / 休整。

### 设计立场

- **战斗解耦**：战斗内的结果只分输赢；战内血量、状态、卡组临时变化都不带出。
- **战外承接**：战后战损通过压力系统、卡牌池、节点消耗等战外机制传达，战前准备和战外运营反向影响下一场战内。
- **三时态**：战前准备 → 战内决策 → 战后结算压力与卡牌流转。

### 玩家手的思维惯性

- **左手 = 援助 / 右手 = 破坏**
- 这条惯性既是叙事基调，也是事件分支选项的默认排版逻辑（左选项偏正向、右选项偏负向）。
- 在卡牌侧体现为左手卡 / 右手卡的效果定位；在事件节点侧体现为同一事件的左右分支收益与代价对称。

### 目标体验

玩家每一回合都应面对清晰但有压力的选择：

- 高 Cost 牌能获得强效果，但可能让多个敌人部位立刻行动。
- 低 Cost 牌更安全，但可能错过完美释放或关键击破窗口。
- 同一张牌处在不同手牌区域时，价值可能完全不同。
- 打出左手牌或右手牌会改变整个手牌结构，带来短期收益和区域失效风险。
- 击破敌人关键部位可以改变战斗节奏，但敌人并不一定立刻死亡。

战外则面对另一组压力：

- 时段节点是有限资源，每个节点要做战斗 / 探索 / 商店 / 休整的取舍。
- 每条战内决策都会留下战外代价：HP 跨阈值留伤口，永久销毁伙伴卡留嗜血，节点流转累计饥饿 / 疲劳 / 腐朽。

### 游戏循环

**Run 循环**：

```
进入区域 → 进入大地图（迷雾遮挡）→ 沿通道在节点间移动 → 触发节点事件（战斗/商店/事件/休息/卡组管理）
→ 已揭示节点永久可见，允许回头
→ 时段节点用完自动推进下一时段
→ 一天结束（清晨 → 日间 → 黄昏 → 夜间 → 日出 → 清晨）
→ 任一战外失败条件触发则 Run 结束
```

**战斗循环**：

```
战斗开始 → 当前 HP 拉满到最大 → 初始化备战卡组、敌人部位
→ 玩家回合开始抽牌 → 玩家执行回合操作：打牌/等待/结束回合
→ 敌人部位可能因先机归零在玩家回合内行动
→ 玩家主动结束回合 → 存活部位按顺序行动 → 进入下一回合
→ 全部部位破坏后胜利 / 玩家战内 HP 归零后失败
→ 战斗结束：战内累计的伤口、经验、击倒选择等回传 Run 层
```

## §2 核心玩法

### Cost 风险模型

- 卡牌 `Cost` 表示打出该牌后减少敌方所有存活部位的当前先机值。
- `Cost` 不消耗玩家 AP / EP。
- 战斗中可以出现 `Runtime Cost` 修正，完美释放判断和先机扣减都使用当前 `Runtime Cost`。
- 例如某牌基础 `Cost = 3`，被降到 `Runtime Cost = 2`，则按 2 判断完美释放，也按 2 扣减敌方部位先机。

### 费用转移

- 一张卡的 Cost 可以被临时降低，降低值可以转移到另一张卡上。
- 当前战斗内生效，可叠加。
- 示例：被腾挪卡 `Cost = 3`，被降低 1 点 Cost；这 1 点转移给朝光暮蝶，使朝光暮蝶 `Cost 0 → 1`。

### 费用合法性

```
Enemy Initiative Sum = Sum(Living Enemy Parts CurrentInitiative)
if CardRuntimeCost > Enemy Initiative Sum → 卡牌不可用
```

### 手牌空间

手牌不是普通线性列表，而是由左手牌和右手牌切分出的空间结构：

```
[左手区] [左手牌] [双手区] [右手牌] [右手区]
```

不同区域会改变卡牌价值（区域效果）。腾挪操作让玩家通过调整手牌空间来制造区域效果、完美释放机会和 Cost 转移。

### 部位制敌人

敌人由多个部位组成，每个部位近似一个独立战斗单元。部位 HP 归零后进入破坏态，全部部位破坏后战斗胜利。

### 完美释放

如果打出的卡牌 `Runtime Cost` 正好等于某个敌方部位在出牌前的当前先机，则该部位触发完美释放效果。多个部位可同时命中。迅捷卡不触发完美释放。

完美释放应当成为玩家主动规划的关键收益，而不是偶然出现的小加成。

### 等待

等待是不消耗手牌的节奏调节手段：

- 所有敌人部位当前先机减少当前等待值。
- 等待结算后，当前等待值 +1。
- 每回合开始时等待值重置为 2。
- 等待不触发完美释放。

## §3 玩家

玩家拥有：

- 手指数量（决定本体 HP 上限）
- 当前 HP（战内独立维护，战外不作为交互对象）
- 战外背包（永久卡牌池，由"背包卡"提供能力，详见 §11）
- 备战区（从玩家拥有的卡牌中选出的子集，战斗只读它）
- 左手牌和右手牌（角色固有）
- 压力（八种状态的累计百分比）
- 经验值与角色技能池

### §3.1 血量系统

#### 玩家本体 HP 上限

```
PlayerBaseMaxHp = FingerCount × HpPerFinger
```

- `HpPerFinger = 2`（默认数值化常量，可调整）
- 默认角色 `FingerCount = 10`，本体上限 = 20 HP
- 不同角色可以有更多或更少手指

#### 战内 HP 上限

```
BattleMaxHp = PlayerBaseMaxHp + Σ(备战卡组中带 Companion 关键词的卡的 MaxHpBonus)
```

- **只有带 `Card.Keyword.Companion` 关键词的卡**才会把 `MaxHpBonus` 计入战内 HP 上限。
- 武器 / 工具关键词若同时带 Companion（如烁光蝶 = 伙伴/武器/连击），仍然计入。
- 没有 Companion 关键词的卡即便填了 `MaxHpBonus` 也不计入。

#### 战内 / 战外 HP 关系

- **战外 CurrentHp 不作为交互对象**：战外没有"扣血"或"回血"概念，等价于当前战外的 HP 上限。
- **每场战斗开始时 CurrentHp = BattleMaxHp**（战斗内 HP 拉满）。
- **战内损血不带出战外**：本场战斗中扣的血在战斗结束时被丢弃，下一场战斗重新拉满。
- 战内损血改为以**伤口压力**的形式映射到战外（见 §3.2）。

#### 额外生命值（Shield）

- 战内额外生命值 = 现行 Shield 字段的正名。
- 优先结算除中毒外的所有伤害，扣完才扣 CurrentHp。
- **中毒穿透额外生命值**，直接扣 CurrentHp。

#### 失败条件

满足任一即败：

| 维度 | 条件 |
|---|---|
| 战内 | CurrentHp = 0 且敌人未被全部击败 |
| 战外 | 压力 8 条加和 ≥ 100% |
| 战外 | 手指数量 = 0 |

战外两条独立判定（压力满 与 手指掉光 各自结算）。

### §3.2 压力系统

压力是战外"血量"，是负面状态的集合。

- **总值 = 8 条压力百分比之和**，达到 100% Run 失败。
- **压力对战内规则零影响**。压力的"状态效果"只是显示层（卡面变化、咳嗽音效、移动速度变慢等）。
- 战外事件可以读取压力值产生事件分支或限制选项。
- 压力可以**减少 / 归零**，每条状态各自有"减少条件"——**第一阶段实现减少机制，具体减少条件占位待定**。

#### 八种压力状态

| 状态 | 触发条件 | 状态效果（显示层）|
|---|---|---|
| 饥饿 | 每**清晨**或**黄昏**到来 +5% | - |
| 伤口 | 战外右手破坏行为 +1%（节点事件分支）<br>战内首次跨过 `CurrentHp/MaxHp < HighHpThreshold` +1%<br>战内首次跨过 `CurrentHp/MaxHp < LowHpThreshold` +5%<br>战内 `CurrentHp = 0` 且与敌人同归于尽 +10% | 添加牌面伤口效果 |
| 疲劳 | 每**日出** +10%<br>每场战斗后 +1%（不分胜败）| - |
| 负重 | 每拥有超出通量存放区容量的 n 张牌 +(n(n+1))/2 % | 战外移动速度减少 |
| 腐朽 | 每完成一天 +5% | 时不时咳嗽 |
| 劣迹 | 每完成 n 次偷窃行为 +(n(n+1))/2 + 1 % | - |
| 嗜血 | 每**永久销毁**一张伙伴卡（消耗 / 战败丢弃 / 出售）+1% | - |
| 残疾 | 每缺少一根手指 +5% | 改变手卡卡面 |

#### 阈值常量化

`HighHpThreshold` / `LowHpThreshold` 等数值都作为可调常量配置，**不在代码中硬编码**。第一版默认值：

```
HighHpThreshold = 0.5  ← 玩家 HP 剩 50% 以下首次触发，+1% 伤口
LowHpThreshold  = 0.2  ← 玩家 HP 剩 20% 以下首次触发，+5% 伤口
```

含义说明：阈值是 `CurrentHp / MaxHp` 小于该值。HighHpThreshold 数值更大（玩家伤得更轻就触发），加成更小；LowHpThreshold 数值更小（伤得更重才触发），加成更大。两个阈值各自独立判定，可同时跨越（如玩家从满血直接被打到 13% → 首次跨 0.5 +1，首次跨 0.2 +5，合计 +6%）。

后续可通过角色定义或 Run 配置调整。

#### 战内 → 战外 回传

战斗内只跟踪 flag、计数和事件标记，不直接修改压力。战斗结束时统一回传给 Run 层结算。例：

| 战内事件 | 回传内容 | Run 层处理 |
|---|---|---|
| 首次 `HP/MaxHp < HighHpThreshold` | `bCrossedHighHpThreshold = true` | 伤口 +1% |
| 首次 `HP/MaxHp < LowHpThreshold` | `bCrossedLowHpThreshold = true` | 伤口 +5% |
| 同归于尽 | `bMutualDestruction = true` | 伤口 +10%（不触发 Run 失败）|
| 击倒部位经验 | `KnockdownExpGains[]` | 经验值累加 |
| 击倒事件玩家选择 | `KnockdownChoices[]`（援助 / 破坏 / 撤离）| 触发对应事件分支 |
| 战斗结束 | 一律 | 疲劳 +1% |

战内 flag 在 BattleSession 内维护；战斗结束时打包成"战后结算包"传给 RunSession 统一处理。

### §3.3 经验值与角色技能

#### 经验值

- 经验值是敌人 / 卡牌 / 事件的奖励。
- **战内击倒一个敌人部位 = 一份经验值**（数值由部位定义提供）。
- 击倒事件中玩家可在三种选项中选一：左手援助 / 右手破坏 / **撤离**。撤离也结算该部位的经验值。
- 战内经验**先记账不入账**，战斗结束统一发放给玩家累计经验值。
- 累计经验达到经验值上限（默认 10）→ 获得 1 次技能并清零累计经验。

#### 角色技能池

- 技能 = 战外永久属性 / 被动。
- 技能一旦获得，**所有后续战斗都享**。
- 技能池属于角色（不同角色技能池不同）。
- **第一阶段先做"经验累计 + 满 10 触发"机制**，技能内容用占位（例如 +HP 上限、+经验值上限）。

### §3.4 手与手指

- 玩家角色默认拥有左手牌和右手牌，以及 10 个手指。
- 手指影响本体 HP 上限（每指 2 HP）。
- 失去手指会同时累计**残疾**压力（每缺 1 指 +5%）。
- **失去 5 个手指**：玩家会失去一张左 / 右手牌（先失去哪张暂定）。
- **失去 10 个手指（手指 = 0）**：战外失败立刻触发。
- "压力 8 条加和 ≥ 100%"和"手指 = 0 失败"是两个独立判定，可以同时命中（总压力达不到 100% 但手指掉光也会立刻败）。
- 每次失去手指时，左 / 右手牌发生卡面变化（显示层）。

### §3.5 左手牌与右手牌

- 左手牌 / 右手牌是每个角色初始自带的核心牌，也是手牌区域锚点。
- 不同角色的左 / 右手牌可以有不同效果和 Cost。
- 它们本身是普通卡牌，可以被打出。
- 打出后离开手牌，不进入任何卡牌区域（进入 Limbo）。
- 回合开始时强制抽回。
- 自带保留效果。
- **角色固有，不可永久删除**（见 §4.4）。

## §4 卡牌设计

### §4.1 基础属性

卡牌至少包含：

| 属性 | 说明 |
|---|---|
| 名称 | 显示名 |
| Cost | 打出后扣减敌方先机的值 |
| 身材（可选）| 入战属性（生命值上限、耐久、容量等）|
| 类型 / 词条 | 关键词标签 |
| 稀有度 | 白 / 蓝 / 固有 |
| 效果 | 主动效果列表 |
| 被动（可选）| 不需要主动打出也能响应事件的效果 |
| 区域效果（可选）| 根据所在区域触发的额外效果 |
| 完美释放效果（可选）| 命中完美释放时的额外效果 |

### §4.2 关键词

| 关键词 | 说明 |
|---|---|
| 迅捷 | 打出时不减少敌方部位先机，不触发完美释放 |
| 伙伴 | 卡牌词条，不作为场上实体被攻击；带身材的伙伴卡的 `MaxHpBonus` 计入战内 HP 上限 |
| 连击 | 使用后可重复使用，打出后留在原位置 |
| 保留 | 回合结束时不弃掉 |
| 武器 | 卡牌词条 |
| 工具 | 卡牌词条 |
| 突袭 | 暂未定义 |

### §4.3 卡牌分类

正交两个维度：

#### 归属维度

- **角色卡牌**：该角色专属（虫妹的飞蛾蝶蛉等）
- **中立卡牌**：通用池，任何角色都能进背包
- 第一阶段实现：只做角色卡牌，**`UCardDefinition` 字段不预留中立 / 归属字段**。等策划补充中立卡需求后再扩。

#### 稀有度维度

- 白
- 蓝
- 固有 = `Card.Rarity.Intrinsic`
  - **"角色固有" = 稀有度 Intrinsic**，仅命名等价。
  - 不为它额外定义"不可永久删除"等约束，等策划完善后再补。

### §4.4 已确认卡牌细则

#### 朝光暮蝶

- `Cost = 0`，身材：1 生命值上限，词条：伙伴，稀有度：白
- 入战时角色生命值上限 +1，当前生命值 +1
- 随机腾挪 1 张我方卡牌（范围：当前手牌）
- 施加等于此卡当前 RuntimeCost 的中毒（目标：指定敌方部位）
- **左手区 + 完美释放**：本次打出不减少敌方部位先机（不作为真正"迅捷"关键词）
- **右手区**：通过此卡腾挪的卡牌 Cost -1，减少的 1 点转移到朝光暮蝶上（可叠加）

#### 拂晓飞蛾

- `Cost = 0`，身材：1 生命值上限，词条：伙伴，稀有度：蓝
- 入战时角色生命值上限 +1，当前生命值 +1
- 对一个敌方部位施加 1 减速
- **被动**：每当你在本场战斗内打出三张伙伴牌时，使此牌从所有非手牌区域回到手牌
  - "三张伙伴"是战斗内全局计数，触发后计数清零

#### 赤腹工蚁

- `Cost = 0`，身材：1 生命值上限，词条：伙伴 / 保留，稀有度：白
- 入战时角色生命值上限 +1，当前生命值 +1
- 将双手区域的随机 1 张卡牌腾挪至其他区域（排除双手区，目标为左手区或右手区）
- 如果双手区不存在，则此牌不能打出

#### 烁光蝶

- `Cost = 1`，身材：6 生命值上限，词条：伙伴 / 武器 / 连击，稀有度：白
- 入战时角色生命值上限 +6，当前生命值 +6
- 造成 7 伤害（目标：当前选中的敌方部位）
- **连击**：使用后可重复使用
- **被动**：每当你打出此牌后，该牌腾挪至随机区域（覆盖连击默认回原位的口径）

#### 暮蛉

- `Cost = 5`，身材：23 生命值上限，词条：伙伴，稀有度：蓝
- 入战时角色生命值上限 +23，当前生命值 +23
- 冻结一个敌方部位 1 回合
- 突袭：暂未定义，先不进入第一版实现
- **被动**：当触发暮气时，使一张中毒卡牌效果 +1
  - "触发暮气"指暮气状态生效
  - "中毒卡牌"指效果里包含施加中毒的卡牌
  - 随机范围是手牌、抽牌堆、弃牌堆
  - 如果该牌有多个中毒相关效果，则全部中毒层数 +1

#### 暮色引虫灯

- 首先是一张卡牌
- 身材：1 耐久 / 3 容量
- 1 耐久 = 战斗中可打出一次，打完进消耗区
- 3 容量 = 增加背包上限 3
- 占用手牌区域，相当于正常卡牌
- 任务完成后升级这张卡牌

## §5 手牌区域

### 区域结构

```
[左手区] [左手牌] [双手区] [右手牌] [右手区]
```

- 左手牌左边为左手区
- 右手牌右边为右手区
- 左手牌与右手牌之间为双手区
- 每个区域容量暂时没有上限

### 区域判定

- 两张锚点都在手牌区时：左手牌左侧 = 左手区，中间 = 双手区，右手牌右侧 = 右手区
- 只有一张锚点在手牌区时：锚点左侧 = 左手区，锚点右侧 = Zone None，双手区不存在
- 两张锚点都不在手牌区时：所有普通卡牌 Zone = None
- 锚点本身 Zone 始终为 None

### 腾挪

- 腾挪表示重新放置当前手牌中的卡牌，使其进入不同手牌区域或在同一区域内改变位置。
- 腾挪范围默认是当前手牌中的普通卡牌（第一阶段默认不选择左手牌和右手牌）。
- 腾挪到目标区域时，插入目标区域内的随机位置。
- 如果随机目标区域等于当前区域，仍然会发生区域内重新放置。
- "从双手区腾挪到其他区域"：目标排除双手区，只能是左手区或右手区。
- "左方没有卡牌"指左手区没有牌（不是相邻位置为空）。

### 双手区失效

- 左手牌或右手牌离开手牌区时，双手区立刻失效。
- 原双手区中的牌仍保留在手牌中，但不再属于任何区域（Zone = None）。
- 腾挪可用区域缩减为仅 Left（锚点左侧）。
- 如果左右手牌都不在手牌区，所有普通卡牌 Zone = None，腾挪不可用。

### 手牌队列生成

- 回合开始固定从抽牌堆抽取 5 张普通卡牌。
- **左右手牌都不在手牌区**：先形成预备队列，再将左手牌和右手牌插入（两者之间至少一张普通卡牌）。
- **左右手牌都在手牌区**：不移动已有卡牌位置，新抽卡随机插入当前手牌区。双手区中被保留的卡牌保持原有相对位置。
- **只有一张锚点在手牌区**：按"都不在"的规则重新生成完整结构。

### 手牌上限

- 普通卡牌手牌上限为 10（不计算左手牌和右手牌）。
- 算上左右手牌后，最终手牌队列上限为 12。
- 超过上限的普通卡牌移动到弃牌区。

## §6 敌人与部位

### 敌人结构

一个敌人由多个部位组成。每个部位拥有：

- HP
- 当前意图（Intent）
- 当前先机（CurrentInitiative）
- 状态（Status）
- 部位顺序

### 部位破坏

- 部位 HP 归零后进入破坏态。
- 被破坏部位不再拥有意图和先机值。
- 被破坏部位不再参与先机扣减、意图刷新和行动结算。
- 不再作为普通目标被选择（除非卡牌明确允许）。

### 部位击倒

> "击倒"为暂定名词，后续可能更换。下文统一沿用"击倒"作为占位术语。

以蛇为例：

- 蛇有头、身体、尾巴三个部位。
- 蛇头 HP 归零后触发**头被破坏**，同时触发**该部位的击倒事件**（针对被破坏的部位本身，而非整只敌人）。
- 敌人不会因此直接死亡。全部部位被破坏后才算战斗胜利。
- 同一场战斗中，每个部位破坏时各自独立触发一次击倒事件。

### 同归于尽

战斗结束判定时若 **敌方所有部位破坏 + 玩家 CurrentHp = 0** 同时发生：

- 战内 Outcome 仍判 **Victory**
- BattleState 置 `bMutualDestruction = true`
- BattleSession 把该 flag 通过 `FBattleResultPacket` 传给 RunSession
- 战外 +10% 伤口压力
- **不触发战外失败**（玩家 Run 继续）

实现位置：`FBattleRules::CheckAndApplyBattleEnd`。

### 击倒事件（玩家三选一）

某个部位被击倒时，针对**该部位**提示玩家选择：

- **左手 = 援助**：使用当前手牌中的左手牌处理击倒事件，触发援助类分支。
- **右手 = 破坏**：使用当前手牌中的右手牌处理击倒事件，触发破坏类分支。
- **撤离**：不使用左 / 右手，直接结算该部位的经验值。

附加规则：

- 如果已打出左手牌，"左手"选项不可用。
- 如果已打出右手牌，"右手"选项不可用。
- 如果左 / 右手都不在手牌中，给默认奖励或仅留撤离。
- 无论选哪个，**部位经验值都会结算到战后经验值累计**。

### 先机与完美释放

- 先机是敌人部位的行动倒计时。
- 玩家打出非迅捷卡牌后，所有存活部位当前先机减少该牌 `RuntimeCost`。
- 如果部位先机归零或低于零，该部位按固定顺序行动，然后刷新意图和先机。
- **完美释放判定**：出牌前记录所有存活部位的 CurrentInitiative。若 CardCost == Part.CurrentInitiative，则该 Part 命中 PerfectRelease。随后若卡牌不具备迅捷，统一扣减所有存活部位 CurrentInitiative。
- 某些卡牌可以在"区域条件 + 完美释放条件"同时满足时，让本次打出不减少敌方部位先机（不实现为提前给卡牌添加"迅捷"关键词）。

### 抵抗

- 先机命中时触发抵抗判定（先于完美释放）。
- 卡牌效果数值 vs 敌人意图数值进行比较。
- 如果卡牌抵抗值 > 意图抵抗值，该部位进入晕厥状态。
- 晕厥以层数模型记录，每次行动消耗 1 层。

### 部位行动规则

- 多个部位同时先机归零时，按部位顺序依次行动。
- 每个部位的每个意图自带先机值。
- 部位执行意图后，刷新到新意图，当前先机设为新意图的先机值。
- 部位在玩家回合内因先机归零行动后，玩家结束回合时仍会再次行动。

## §7 状态与效果

### 中毒

- 可叠加层数模型。
- 敌人有多个部位时，每个部位可以各自拥有中毒。玩家本体也可以拥有中毒。
- **触发时机**：玩家每打出一张牌后 + 敌方部位每行动一次后，对敌我双方各结算一次当前中毒层数伤害。
- 中毒伤害穿透额外生命值，直接扣除当前 HP。
- 层数不因结算而减少（持续存在直到被治疗或其他效果移除）。
- 被治疗时，移除治疗效果 10% 的中毒层数（向下取整）。

### 减速

- 基础控制类型。
- 使敌人当前意图延迟倒计时（增加当前先机值）。
- 施加给玩家时：玩家回合开始时使每张卡牌费用临时增加，回合结束时清除。
- "x 对应对象个数，y 代表程度"——对 2 个目标施加 3 减速表示每个目标先机 +3。

### 暮气

- 基础控制类型。
- 使敌人下一次意图延迟倒计时到来，生效后减少一半层数（向下取整）。
- 施加给玩家时：玩家回合开始时使每张牌的费用上限增加。使用沾染暮气的卡牌后，该牌层数减半。
- 回合结束后，洗入牌库的暮气仍然存在。

### 冻结

- 基础控制类型。
- **施加给敌方部位时**：该部位下一次行动跳过当前意图（与晕厥共享"跳过 + 消耗 1 层"分支）。
- **施加给玩家时**（未实现）：玩家回合开始时使每张牌不可被打出。使用相邻牌时解除冻结状态。
- 玩家所打出的牌仍需遵守其费用小于等于敌人倒计时总和。

### 连击

- 使用此牌后可重复使用。
- 非特殊情况，该牌打出后回到原位置。
- 连击与手牌区域变化、左手 / 右手离开、双手区失效之间需要单独定义。

### 晕厥

- 由抵抗判定施加。
- 层数模型，每次该部位行动（无论执行意图还是因晕厥跳过意图）都消耗 1 层。
- 层数归零时晕厥状态移除。

### 额外生命值（Shield）

- 战内护甲资源。
- 优先结算除中毒外的所有伤害。
- 中毒穿透。

## §8 时间与昼夜

### §8.1 一天结构

一天由五个时段顺序更替组成：

```
清晨 → 日间 → 黄昏 → 夜间 → 日出 → 清晨（次日）
```

- 任一时段节点全部消耗时，**自动**推进到下一时段。
- 玩家不需要主动"结束时段"。
- 露营结束是**特殊推进**：直接跳到次日清晨，跳过夜间剩余节点和日出。

### §8.2 时段初始节点数

| 时段 | 初始节点数 | 开始事件 | 备注 |
|---|---|---|---|
| 清晨 | 2 | 触发"清晨规划"事件，事件本身消耗 1 节点 | 实际剩 1 个可用节点 |
| 日间 | 6 | - | 主流程与事件 |
| 黄昏 | 2 | 选择是否触发"野炊"事件 | 野炊按 1 个正常节点算 |
| 夜间 | 2 | 选择"露营"或"夜间探险" | 见下文 |
| 日出 | 1 | - | 算作前一天的后置奖励 |

### §8.3 节点 = 资源点

- **节点数是有限资源**，可被事件 / 角色技能 / 卡牌效果增减。
- 把它当资源点设计：每个节点都是一次"机会"，错过就过。
- 战斗节点 = 占用 1 个时段节点。

### §8.4 时段细则

#### 清晨

- 总 2 节点。
- 时段开始时立刻触发"清晨规划"事件，**消耗 1 节点**（可在此事件中影响当日节奏 / 增减节点）。
- 剩下 1 节点用于其他事件。

#### 日间

- 总 6 节点。
- 全部用于主流程事件、战斗、商店、休息等。

#### 黄昏

- 总 2 节点。
- 时段开始时玩家选择是否触发"野炊"事件：
  - **触发野炊**：作为 1 个正常节点消耗，剩 1 节点为正常事件。
  - **不触发**：2 节点都是正常事件。

#### 夜间

- 总 2 节点。
- 时段开始时玩家选择"露营"或"夜间探险"：
  - **露营**：用 1 节点进入露营事件。露营事件是一个**大事件集合**（升级卡 / 调整背包 / 学技能等子事件可选）。
    - 露营本身消耗 1 节点，子事件不再消耗节点。
    - 露营结束 = 睡觉休息，**直接进入次日清晨**（跳过日出，剩余 1 个夜间节点不结算）。
  - **夜间探险**：2 节点都是探险事件，全部消耗后进入**日出**。

#### 日出

- 总 1 节点。
- 算作前一天的后置奖励，结束后进入次日清晨。
- 仅"夜间探险"路径会进入日出。"露营"路径直接跳过。

### §8.5 节点 = 事件

- 节点是流程最小单位，**本质是一个事件**。
- 节点静置分布于地图之上并通过通道相连（通道不是节点）。
- 节点三时态：
  - 开始 = 玩家发起交互行为（查看商店、与人交流、触发战斗等）
  - 进行中 = 事件执行
  - 结束 = 行为完成或玩家主动退出
- **第一阶段所有节点串行**（含战斗节点）。"节点可并行"是 NewContent 的长期方向，留进 §14。

---

## §9 事件系统

事件是节点的执行内容。所有节点（含战斗节点）统一通过事件系统调度。

### §9.1 事件分类

- **战斗事件**：进入一场战斗。规则细节见 `WacomBattle.md`。
- **商店事件**：进入商店界面进行交易。
- **探索事件**：分支选择型事件，左手 / 右手分支多次出现，呈现思维惯性。
- **休息事件**：恢复或调整状态（具体细节随营地等大事件而定）。
- **特殊事件**：清晨规划、黄昏野炊、夜间露营、日出等时段绑定事件。

### §9.2 战内 → 战外回传

战内事件结束时（即一场战斗结束），将战内累计的"可能影响战外"的数据打包回传 RunSession。已确定的回传项：

| 回传字段 | 战内累计方式 | 战外处理 |
|---|---|---|
| `bCrossedHighHpThreshold` | 战内首次跨过 `HP/MaxHp < HighHpThreshold` 时置 true | 伤口压力 +1% |
| `bCrossedLowHpThreshold` | 战内首次跨过 `HP/MaxHp < LowHpThreshold` 时置 true | 伤口压力 +5% |
| `bMutualDestruction` | 战内 `HP = 0` 且敌方未全死时置 true | 伤口压力 +10%，且**不触发战外失败**，玩家继续 Run |
| `KnockdownExpGains[]` | 击倒部位时记账（含撤离选择）| 经验值累加，满 10 入技能池 |
| `KnockdownChoices[]` | 玩家在击倒事件中选的"援助 / 破坏 / 撤离"| 触发对应分支事件（援助走援助分支，破坏增加伤口或劣迹等）|
| `bBattleFinished` | 战斗结束统一为 true | 疲劳压力 +1% |

阈值 `HighHpThreshold` / `LowHpThreshold` 是数值化常量，第一版默认 `0.5 / 0.2`。

### §9.3 战外行为 → 压力

战外节点事件中的行为按 §3.2 表格直接累加压力。例如：

- 节点事件分支选了"右手破坏" → 伤口 +1%
- 节点事件分支完成偷窃 → 劣迹累计 +(n(n+1))/2 +1 %
- 节点事件中永久销毁一张伙伴卡 → 嗜血 +1%

### §9.4 时段事件触发

- 时段切换由 RunSession 自动管理（节点用完自动推时段）。
- 时段开始 / 结束的事件（清晨规划、黄昏野炊、夜间露营 / 探险）由 RunSession 在时段三时态切换时主动调度。

## §10 Run 与地图

### §10.1 地图结构

- 地图由**节点**和**通道**构成。
- 节点静置分布于地图之上，通过通道相连。
- **节点是事件载体**（见 §8.5 / §9）；**通道只是连接，不是节点，本身不承载事件**。
- 第一阶段：**一张大图覆盖整个 Run**。所有时段共享同一张地图，节点对所有时段都可见 / 可达。
- 时段切换不切换地图，玩家位置保留（停在哪就从哪继续走）。

### §10.2 迷雾与揭示

- **首次进入地图**：所有节点被迷雾遮挡。
- **可见集**：玩家所在节点 + 通过通道直连的相邻节点。
- 玩家走过（站立过）的节点**永久揭示**，下次进入也保留可见状态。
- 已揭示节点周围一圈通过通道相连的节点也保持可见（即"可见集"始终基于当前已揭示节点的并集）。

### §10.3 通道

- 第一阶段所有通道**一律双向**。
- 通道不消耗节点数（移动本身免费）。
- 通道单向限制（悬崖、水流等）作为长期方向，进 §14 待确认。

### §10.4 节点消耗规则

节点数是时段资源（见 §8.3）。节点消耗发生在**事件触发时**，不是踏上节点本身。

| 行为 | 消耗节点数 |
|---|---|
| 沿通道在地图上移动（不触发事件）| 0 |
| 进入未走过节点但不触发事件（"看一眼就退"）| 0 |
| 触发未走过节点的事件 | 1（事件结束时结算）|
| 触发已走过节点的事件（按事件可重入规则）| 见 §10.5 |
| 战斗节点撤离 | 1（详见 §10.5）|

### §10.5 节点可重入规则

事件类型决定节点可否重入：

- **一次性事件（默认）**：消费 = 一次性。已触发完成的节点变为空节点，可站立 / 通过，但不再有可交互内容。例：普通事件、休息事件。
- **可重入事件**：可被反复触发。每次触发结算 1 节点。例：商店（可重复进出买卖）。
- **战斗节点**：玩家进入战斗节点时触发战斗。
  - **节点结算时机**：战斗结束统一结算 1 节点（不论 Outcome：胜利 / 失败 / 撤离都消耗）。**触发战斗本身不立刻消耗**——避免"刚进战斗就因节点结算推进时段"的边界情况。
  - 战斗内允许撤离。撤离不退还已消耗的节点数（已结算）。
  - 撤离后玩家回到**进入战斗节点前的通道**或**回到战斗节点本身让玩家选择去往的通道**（具体撤离回退点由战斗事件决定，第一阶段实现 ExitBattle 回探索原坐标）。
  - **撤离的部位破坏状态持久化**：撤离时记录该 Trigger 对应敌人**已破坏的部位列表**。下次进入同一战斗节点时，已破坏的部位维持破坏态（无 HP / 无意图 / 不参与先机），未破坏的部位满血开始。这部分状态以 `ABattleTriggerActor.PersistentId` 为索引存入 `FRunState.BattleProgress`。
  - **撤离 Outcome ≠ Victory**：敌人不进 `DefeatedEnemies`，战斗节点不变"已完成"。同一节点下次进入仍触发战斗。
  - **战斗胜利**：节点变为已完成（一次性，不可再战）。Trigger 标记为已销毁，BattleProgress 中该 Trigger 的进度可清理。
  - **战斗失败**：Run 结束。
  - **击倒事件经验**：只在当次战斗中"部位 bDestroyed false→true 边沿"结算。预先破坏（来自 BattleProgress 的）部位不再发经验，避免反复撤离刷经验。

### §10.6 时段切换与玩家位置

- 时段节点用完自动推进下一时段。
- 时段切换**不传送玩家**。玩家停在哪个节点 / 通道上，下个时段从同位置继续。
- **露营特殊推进**：露营结束后玩家**留在营地节点**（不传送），从营地节点开始次日清晨。

### §10.7 节点事件配置策略

- **第一阶段：预先固定**。地图设计阶段为每个节点指定事件类型和具体内容。
- **接口预留**：`UMapNodeDefinition` 或等价数据结构留出"事件配置策略"字段，后续可切换为：
  - 按权重 / 规则随机生成
  - 混合（地图骨架固定，事件随机）
- 第一阶段骨架先按预先固定走，但数据结构不要写死成"必须配置事件"，给随机生成留接口。

## §11 背包与构筑

### §11.1 设计立场：万物成卡

本游戏底层逻辑是"万物成卡"——背包能力本身也是一张卡牌赋予的：

- 没有任何"背包卡"时，玩家**打不开背包 UI**
- 背包卡（容器卡的一种）通过自身的 `Capacity` 字段贡献存放空间
- 玩家每个角色初始持有一张基础背包卡（虫妹默认 = "虫妹的小布袋"）

### §11.2 卡牌容量分类

每张卡有 `Capacity` 字段（来自 `FCardPhysique.Capacity`）：

| Capacity | 分类 |
|---|---|
| `0` | **普通卡**：本身不贡献存放空间。第一阶段所有卡默认 0。 |
| `> 0` 且**无容量效果** | **A 类容器卡**：作为通量存放区主卡，贡献空间到通量存放区。如"虫妹的小布袋" Capacity=12。 |
| `> 0` 且**有容量效果** | **B 类容器卡**：作为特殊存放区主卡。每张 B 类主卡独立展开一个特殊存放区，放进去的卡在满足条件时获得该主卡的容量效果。 |

**容器卡关键词**：

- `Card.Keyword.BagProvider`：**只要背包里至少有一张此关键词卡**，背包 UI 才能打开
- 第一阶段虫妹的小布袋是唯一带 BagProvider 的卡

### §11.3 背包区结构

```
背包区
├── 通量存放区（始终一个，由所有 A 类主卡共同支撑）
├── 特殊存放区(b1)   ← B 类容器卡 b1 独自开辟
├── 特殊存放区(b2)   ← B 类容器卡 b2 独自开辟
├── ... 每张 B 类容器卡各开一个
└── 特殊存放区(负重)   ← 超容时显示，超容卡进这里
```

通量存放区和普通特殊存放区都由两个子区域组成：

```
存放区
├── 主卡区：放提供容量 / 容量效果的主卡
└── 内容区：放被该存放区收纳的卡牌
```

- A 类主卡可以堆叠在同一个通量存放区主卡区。
- B 类主卡不堆叠；每张 B 类主卡独立开一个特殊存放区，因为不同 B 类主卡可能具有不同容量效果。
- 负重区属于背包区中的特殊存放区，但没有主卡区；它只在卡牌超出其他存放区容量后显示。
- 当某张主卡进入备战区时，该卡的物理 instance 位于备战区；背包区对应主卡槽仍显示该卡投影，并标记"已出战"。投影不是第二张卡，不产生新的 InstanceId。

### §11.4 容量公式

```
通量内容容量 = Σ(玩家拥有的所有 A 类容器卡的 max(Capacity - 1, 0))
备战区容量    = Σ(玩家拥有的所有容器卡的 Capacity)
特殊存放区(b) 容量 = b.Capacity - 1
特殊存放区(负重) 容量 = 不固定，超出其他区的卡进入这里
```

**关键约定**：

- 容器卡放哪个区都计入容量来源（"玩家拥有"，不管在背包还是备战区）
- A 类主卡占用通量存放区的主卡区；内容区实际可收纳数量 = `Σ(A 类主卡 max(Capacity - 1, 0))`
- B 类主卡占用自己特殊存放区的主卡区；内容区实际可收纳数量 = `B.Capacity - 1`
- **容器卡被永久销毁后立即停止贡献**，可能导致通量/备战变小，超出的卡溢出到负重区
- 通量存放区和备战区是**两个独立的存放槽**，**一张卡同时只能在一个区**（移到 BattleDeck 即从 Backpack 移除，反之亦然）
- 备战区持有出战卡的物理 instance；背包区显示的"已出战主卡"是投影
- 普通卡占用内容区 1 格；主卡占用主卡区 1 格，不再混入右侧内容区

### §11.5 容量举例

虫妹初始持有：
- 1 张虫妹的小布袋（Capacity=12，A 类容器卡，BagProvider）
- 5 张伙伴卡（Capacity=0）
- 1 张暮色引虫灯（Capacity=3，第一阶段简化为 A 类）
- 左 / 右手卡（Capacity=0，左右手卡始终通过 Character 字段独立加载，不算入背包）

**A 类容器卡 Capacity 之和 = 12 + 3 = 15；通量内容容量 = 11 + 2 = 13**

打开背包：
- 通量内容容量 = 13
- 通量存放区主卡区 = 虫妹的小布袋 + 暮色引虫灯
- 通量内容区初始占用 = 0 / 13
- 备战区容量 = 15
- 玩家手中卡总数 = 1 + 5 + 1 = 7（不算左右手）

如果玩家把虫妹的小布袋放进备战区：
- 通量内容容量 = 13（不变，仍计入）
- 通量存放区主卡区显示虫妹的小布袋投影，并标记"已出战"
- 备战区容量 = 15（不变）

如果玩家永久销毁暮色引虫灯：
- A 类 Capacity 之和 = 12
- 通量内容容量 = 11
- 备战区容量 = 12

### §11.6 备战区

备战区是从玩家拥有卡牌中选出的子集，是**实际进入战斗的卡组**：

- **战斗只读备战区**，未选入的牌留在背包不参战
- 玩家**在背包界面**确定 / 调整备战区（不在每场战斗前选）
- 备战区容量上限见 §11.4
- 战斗结束后备战区**保持预组不变**（GDD 4.2.2 d 策划原话）

### §11.7 删牌区

- 删牌区是另一种"卡牌赋予能力"区域：拖卡到此置换为金币 / 物品
- **能力来源**（长期方向）：由"删牌卡"提供（如暮色引虫灯升级后获得删牌能力）。Stage 4.4 起以 `Card.Keyword.DeleteProvider` 关键词承载，业务侧 `URunSession::IsDeleteFunctionAvailable()` 判定背包中是否存在此关键词卡
- **第一阶段**：删牌区在背包 UI 中**始终显示**，不读 `IsDeleteFunctionAvailable`，`DeleteCardForGold` 也不强制校验。接口先就位，等规则切换为"按需可用"再接入调用点
- 拖卡到此 → 调用 `URunSession::DestroyCardFromBackpack` 永久销毁，并按规则发放金币（具体数值见下）
- 永久销毁的所有限制见 §11.8

#### 删卡置换金币（第一阶段简易）

- 白色 = 1 金币 / 蓝色 = 2 金币（占位数值，等设计经济系统时再调）
- 固有 / 最后 BagProvider 卡：拒绝销毁
- 删伙伴卡 → 嗜血 +1%（GDD §3.2）
- 物品系统第一阶段不做，仅金币置换

### §11.8 永久销毁

任意路径销毁一张卡（删牌区 / 商店出售 / 战败丢弃）：

- 卡从 `Backpack` 移除
- 卡若在 `BattleDeck` 中，同时移除
- 若卡带 `Card.Keyword.Companion` → 嗜血 +1%（GDD §3.2）
- 若卡是**最后一张** `BagProvider` → 拒绝销毁（销毁后玩家会进入"背包打不开 + 失去 Capacity 贡献"状态）
- 若卡的 `Rarity == Intrinsic` → 拒绝销毁（GDD §3.5 左右手卡保护，未来其他 Intrinsic 卡同理）

### §11.9 战内入战属性

- 备战区中带 `Card.Keyword.Companion` 关键词的卡的 `MaxHpBonus` 累加到战内 HP 上限
- 战斗中临时获得带 `MaxHpBonus` 的伙伴卡也立即生效（这场战斗内）。第一阶段无此机制
- 战斗中卡的状态变更（RuntimeCostModifier、临时关键词等）**不影响 RunState**：BattleSession 用 BattleDeck 的副本

### §11.10 战斗结束回流

- 战斗结束后，战内卡牌的状态变更全部丢弃，备战区按战前状态保留（战外修改影响战内，但战内不修改战外）
- 敌人掉落是永久获得，进背包（第一阶段无掉落机制）
- 战斗失败 = Run 失败，不保留本场掉落
- 永久销毁伙伴卡（消耗类掉落 / 战败丢弃 / 商店出售）→ 嗜血 +1%

## §12 美术方向

### 战斗画面

- 敌人部位需要有明确视觉分区。
- 意图和先机应靠近对应部位显示。
- 手牌位于画面下方，保留左手、双手、右手的空间感。
- 打出左手牌或右手牌时，手牌结构变化需要有清晰反馈。

### 氛围方向

当前卡牌示例包含昆虫、暮色、毒、冻结、暮气等意象。美术可以向自然、微光、昆虫、腐殖、潮湿洞穴和黄昏生态靠拢。

## §13 设计原则

- **战斗解耦**：战内只决输赢，战损不带出，战外用压力承接。
- **战外承接**：所有长期系统（压力 / 经验 / 背包 / 节点）都服务于"战前准备 → 战内决策 → 战后结算"的循环。
- **左援助 / 右破坏**：作为思维惯性贯穿事件分支与卡牌设计。
- **节点是资源**：每个节点都是有限机会，玩家在节点上做战斗 / 探索 / 休整的取舍。
- **数值常量化**：所有可能调整的数值（伤口阈值、HP/Finger、节点初始数等）作为可调常量，避免硬编码。
- 先验证战斗节奏，再扩展 Run 外层。
- 先保证规则可读，再追求复杂卡牌组合。
- Cost 是风险，不是资源。
- 手牌位置是策略，不只是 UI 排列。
- 敌人部位要提供不同威胁，而不只是多个血条。
